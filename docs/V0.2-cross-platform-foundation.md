# V0.2.0 portable foundation and verified limits

Configuration discovery and writable paths are independent of the source checkout
and package installation directory. Server-owner absolute overrides are described
in [installation](INSTALL.md). Temporary sources remain private and expiring; export
stays bound to the exact verified candidate and personally operated native approval.

## Platform evidence

macOS Apple Silicon with CPython 3.12 is the demonstrated environment. Intel Mac
and Windows x64 are intended targets; Linux x64 is under investigation. None of
those additional targets has passed actual installation/workflow verification.
No platform port is part of the source-only release.

Windows work still includes drive-letter path admission, private filesystem handles/
ACLs/reparse-point checks, owned-workspace cleanup, subprocess pipe/lifecycle handling,
native human confirmation and equivalent atomic export. Unix process groups, user
ownership/permission operations and selector-on-pipe behavior cannot simply be
bypassed. Keep musical logic, candidate verification and export guards unchanged.

## Intel dependency status

MCP 2.3.0 requires PyJWT with its crypto extra, which brings cryptography. Upstream
[cryptography 49 removed Intel macOS support](https://cryptography.io/en/stable/changelog/).
Do not downgrade to an older security library merely to obtain an Intel wheel.

The [conda-forge index](https://anaconda.org/channels/conda-forge/packages/cryptography/files)
lists current-version 50.0.2 Intel binaries, and its
[feedstock](https://github.com/conda-forge/cryptography-feedstock) lists an Intel ABI3
variant. This is an investigation candidate, not approved installation or support.
Exact hashes, Python/ABI/OpenSSL constraints, security status, full dependency graph
resolution and a real Intel installation/workflow remain unverified. No conda package
has been installed. Do not mix package managers so that a later sync silently replaces
that binary; any future platform recipe needs an explicit reviewed lock.

## Retained renderer

Official Verovio 6.3.0 failed required deferred cross-voice ties. The unchanged
`6.3.0+composerlint.tie1` patch passed authored endpoint/mapping controls. See
[build instructions](INSTALL.md) and [patch provenance](../patches/README.md).
The adapter retains the official base-version gate plus server-owner file hashes
and patched-child identity. An invalid selected build refuses instead of falling back.

Earlier focused path/import/renderer checks and a relocated-wheel stdio session
established the foundation on the existing host; simulations are not additional
platform acceptance. Current source-candidate verification is recorded in
[the candidate review](licensing/source-candidate-review.md).

## Distribution

The first candidate is source-only. Binaries, font resources, vendor source trees,
private configurations, score workspaces and restricted archives stay excluded.
[Renderer reconciliation](licensing/renderer-redistribution.md) distinguishes
source-patch obligations from future binary source/notice/replacement requirements.
Hashes prove identity, not licensing compliance. Publication requires review and
separate explicit approval; no Git operation is implicit in candidate preparation.
